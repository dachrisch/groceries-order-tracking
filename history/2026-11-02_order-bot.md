# 2026-11-02 — Order bot

## What shipped

An order bot that fills the Knuspr cart and learns occasions, plus an
app-wide chat panel and a Bot page.

1. **Product groups + weekly model** (`270f1a82`)
   - Rules-only grouping (leaf category, size bucket, name similarity,
     union-find) with manual merge/split overrides.
   - Shared consumption model used by Inventory and the bot: ≥3 distinct
     weeks, median interval, 2.5× staleness cutoff, time-decayed rate
     (8-week half-life), stock/horizon quantity, occasion exclusions.
2. **Cart execution + runs** (`903001f1`)
   - `knuspr-cart.ts` extracted from the cart controller.
   - `BotRun` records every added item with a reason; deal-aware variant
     choice; guardrails; best-effort undo; order matching and badges.
3. **opencode + chat** (`4f62fdc5`)
   - Generic opencode client (session → prompt → poll → JSON) with
     `OPENCODE_*` env config.
   - Regex intent parser first; LLM fallback only for language.
   - In-memory jobs + `BotPanel` drawer; Bot page Runs/Groups tabs.
4. **Occasions** (`1f47aa67`)
   - Candidate baskets exclude regular weekly items (unless quantity is
     >2× the usual mode).
   - Co-occurrence clustering (support ≥2, lift ≥1.2, Jaccard ≥0.5 merge),
     opencode naming/servings, per-serving quantities.
   - Fuzzy name/alias matching, "X for N" fills, chat corrections, Occasions
     tab and Orders occasion chips.
5. **Dashboard + settings** (`f9e6a219`)
   - `GET /api/bot/forecast`: weekly €/item estimate plus occasions tagged
     this month.
   - Settings card for max €/run, max items, horizon, delivery lead time and
     the opencode toggle.

Also fixed test infrastructure (`a9a3c454`): the in-memory MongoDB server is
stopped after each test file. Previously every file leaked a ~200 MB data
directory into `/tmp` until `mongod` failed to start.

## Decisions

- Occasion quantities are stored per serving; fills scale with `ceil`.
- Overlapping weekly/occasion items are added once at `max` quantity.
- Manual occasion edits (`manualEdits`) survive rebuilds; unedited stale
  occasions are deleted.
- Undo tries `DELETE /api/v1/cart/item` and the per-id decrement, then verifies
  the cart. If Knuspr rejects it, the UI falls back to a cart link.
- Chat jobs are in-memory; simple commands skip the LLM and are instant.
